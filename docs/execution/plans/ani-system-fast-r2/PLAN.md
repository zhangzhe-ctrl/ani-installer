# ANI-system 临时快速部署方案与任务｜r2

状态：待实施。保留 P1～P5 组织；本轮直接使用 .10～.12 的已安装底座，交付旧 ANI 应用与现有 installer 的首装尾部接入。不是为长期升级、自动恢复或所有业务场景认证建立新平台。

## 0. 最新约束与执行边界

### 0.1 以用户下载包为准

用户确认镜像已下载，且允许其与原探测版本不同。**本轮版本依据是实际下载文件中可核验的镜像，不是 reference 或 materials 的旧请求。** 不重拉旧 digest、不追问同一版本差异、不为了统一源码和镜像 SHA 重建整套服务。

接受版本变化不等于接受损坏：外层归档校验、包内文件/manifest/config/layer 一致性及目标架构仍检查。原包、旧请求与校验文件原样保存；实际应用镜像锁/内网引用另存。若旧 metadata 仍指向已被替换的字节，要指出内部不一致并定位正确输入，不能删除校验或捏造“原包通过”。

版本可用性由最小启动及必要 API/数据库适配判断。优先有限配置适配、固定 SQL 或人工步骤。只有具体错误证明无法运行时才提出最小替代建议，不自动降版或从公网换其它镜像。

### 0.2 新分支、新 worktree，不切换并行任务

本机先读取 status 和 worktree 列表，核对 remote main 并固定一次本轮基线。必须创建新分支 `feature/ani-system-fast-20260930` 与旁路 worktree；已有同名分支/目录可能属于别人，新加后缀，不强制接管。不要 `git switch` 原工作树，不 reset/clean/stash、不取走其他任务改动，不反复合并变化中的 main。

进入新 worktree 后才编辑方案、产品代码、测试及文档，明确文件列表提交。真需修改 ANI 源码时为 ANI 仓库另建独立分支/worktree，不修改并行重构目录。默认仅阅读其已提交源码，不重编已下载镜像。

Fedora 独立执行 worktree 与输出目录。所有渲染、格式化、生成、测试、构建、镜像处理、SQL及 cluster 命令在 Fedora。它从本机阶段提交取得同一 SHA，使用 detached HEAD，不手工修改产品文件、不 commit/push。若远端 GitHub 不通，由本机提供 git bundle；不要反复尝试公网。生成结果必须回本机审阅提交，下一轮执行新 SHA。原任务未结束前不能切换执行树。

### 0.3 工作树隔离不等于运行资源隔离

本轮目标为 `172.16.101.10/.11/.12`；`fedora` 为 `chabking@172.16.101.31`。先确认目标身份、kubeconfig、现有应用、命名空间/网关/端口与其它任务占用，再执行本任务应用部署。已有空业务环境可用就用；同名资源已被另一任务管理则暂停那个冲突点，不私自接管或简单更名破坏服务引用。

复用现有实验协调/锁，不造第二套锁。可新增本应用 namespace、Secret/CA、专用空库/账号/桶，以及必要应用工作负载；可重启本任务有明确归属的 Deployment。不得未经明确确认删除现有数据库/PVC/桶、改变共享 PG 角色与密码、清盘、恢复快照、在线切 CNI、覆盖共享 CRD 所有权、动参考源 `100.64.128.1`。不关闭 TLS、鉴权或现有扫描规则。

## 1. P1｜接收实际材料并导入

**目标：** 用用户已有材料把应用镜像送到内网可写仓库，而不是重新进行旧版本取证。

1. 在已有 incoming 或用户给定路径定位镜像包、校验文件，缺路径才一次询问。完整部署参考包已附在本包 reference，原件在 Fedora 则复用。
2. 先看实际格式。此前工具是 Skopeo dir 集合，使用 scripts/ani_images.py verify；其它真实格式使用对应工具，不强制转换所有镜像。校验源文件不在本机执行。
3. 以实际镜像建立 `服务/动态用途 → 下载引用 → 实际 manifest digest → 内网 digest 引用`。原 tag/runtime ID 的不同记为用户已批准替换；不要求与历史同构。两个 model-import-worker 用途不同，不能因同名自动合并；缺一个用途的匹配材料先根据实际版本合同确认，不武断判已齐或重新下载。
4. 用已有可写 Harbor 的本任务项目导入，证书和授权正常配置，回读目标 digest；不推到只读 Hauler。原工具 push 默认预览，用 --execute 才写入；见 scripts/USAGE.md。静态镜像、动态 Job/fetcher、网关注入 extproc/init 都指向实际映射。
5. Chart、CRD、初始化工具优先用现有材料。旧 Chart 和新镜像不匹配时先查实际字段并小范围适配，不把“恢复旧镜像版本”当默认解法。缺项集中给一个补料表，其余任务继续。

**完成：** 应用必需材料可用、有可追溯实际映射。仅导入不等于运行通过；PARTIAL 不能更名冒充完整包。缺的是非选定历史请求可以明确剔出当前选择记录，但不能掩盖必需服务缺料。

## 2. P2｜固定一套应用配置，不做任意组合

**范围保留：** ani-gateway、auth/tenant/task/metering/platform-settings、reconcile-worker；Session Gateway；model-service/import-worker、inference-service/gateway-publisher、动态 fetcher；KB/RAG；Console/BOSS；实际镜像必需的业务 Envoy Gateway/AI Gateway、extproc、authz 配套，Dex 按实际认证路径决定。

1. 从原部署参考有效 spec 整理模板，去 status、UID、旧分配 clusterIP、PV/节点绑定、自动生成租户资源和测试期依赖。原包整体不 apply，也不重新采集参考集群。
2. 检查 ConfigMap 内层 YAML/JSON。Dex 脱敏破坏的 boolean/list 直接重建小配置，不开发新认证方案。JWT、issuer、双方 mint 凭据、Session ticket、mTLS 按实际镜像合同保持匹配；首次生成后复用，不复制原用户凭据。
3. 映射底座 PG/Valkey/NATS、RustFS或RGW、Milvus及监控日志。参考 ANI S3 adapter 名为 minio，新镜像须确认实际支持；TLS/CA、内部地址、浏览器公开地址、region 和 ANI 专用桶权限一起配置，不用 Milvus 限桶密钥。
4. Console/BOSS/API/OIDC/WebSocket/Origin 使用一套参数；DNS/hosts 和浏览器 CA 允许人工设置。只有运行配置确实不能处理才考虑修单个前端镜像，不能默认重新编译全部应用。
5. vCluster/GPU/Kata/LWS/外部模型不自动成为新增基础设施。用实际镜像支持的未配置/停用方式；未配置的模型/RAG能力准确记录，不伪造模型服务正常。

**完成：** 最终实际镜像的一套可执行配置，以及必要秘密关系/有限人工参数。优先产出 Auth/Gateway 启动需要的子集，后续模板可继续补齐。

## 3. P3｜先空库、首管与核心服务

1. 在目标 PG 上使用本任务专用空业务库。迁移身份和应用身份分开；不把底座超级用户交给所有应用。`ani_app` 的底座登录 owner 与旧迁移组角色用途冲突是既有风险；角色跨数据库共享，不得通过随意 ALTER/轮换共享角色解决。
2. 选择匹配实际镜像的一条共享/KB迁移顺序，查重叠后执行；不对当前数据库运行带旧站点连接的历史脚本。执行失败停止依赖部署，检查事务与已完成步骤，不自动 DROP/schema clean/删卷。
3. 首管使用实际镜像的用户名前缀、密码哈希与平台角色关系；已有账号不重置。缺少入口可写固定小脚本或明确人工 SQL。历史迁移严重漂移时给出固定 schema+角色+seed 的有限备选，数据替换必须单独确认，不能导入参考环境业务数据或用户密码 hash。
4. 准备最少的 CA/秘密/认证依赖，让真实 Auth/Gateway 连接新库、缓存和 NATS。检查入口；人工登录结果单列。用户尚未登录或无浏览器不是其他独立部署的阻塞，也不得假称登录通过。

**完成：** 真实初始化和核心服务启动；首管取得方式与待人工项清楚。不为旧系统修复所有历史迁移、重新做全量 RLS 审计或建设用户管理平台。

## 4. P4｜剩余应用与最薄 installer 接入

1. 按实际依赖处理 namespace/秘密/证书/RBAC → 必需网关 CRD/控制器与认证依赖 → 业务初始化 → 后端/worker → 路由与前端。业务 Envoy 与 kcn 专属 Envoy 不复用。共享 CRD 只兼容复用，不抢 field owner、不裁运行必需依赖。
2. 用同一份有限阶段应用脚本完成当前集群部署及人工修复。阶段可以有 init/apply/wait，真实参数由实现确定；不建设新的 DSL、工作流引擎、事务系统或升级框架。
3. 新增默认关闭的 ani-system 开关和一个 role，让现有 `install.sh`/`kk ani install` 在未来干净首装末尾调用相同应用逻辑。关闭开关不影响现有底座。
4. 当前 .10～.12 已有健康底座，独立调用应用阶段，不重放全量 install.sh，不要求先取得一份新的全集 install-success。保留旧记录；独立应用结果不冒充通用 components-run。
5. 原计划第5节通用材料锁扩充本轮不做。现有校验不得移除或篡改；通过清楚标识的应用导入/补装路径使用新材料。最终交付说明包括未来首装所需应用镜像/Chart/初始化工具和现有包的组合方式，但不重建未变底座材料。

**完成：** 必要应用已经部署、相同逻辑接入首装末尾，应用失败仅定点修复与重试。未实施的业务能力有明确说明，不通过默删必需服务伪装完成。

## 5. P5｜最低检查、人工事项和结束

必要检查：实际材料/参数、初始化真实结果、所选必要工作负载 Ready、API/Console/BOSS可达；一次人工登录单列。业务验收、模型/KB全链路、跨租户专项、故障重建/HA与B08～B12都不是本轮交付前置。

允许人工 DNS/hosts/CA、固定初始化、首管、S3策略、个别配置；在一份 WORK-RESULTS.md 中记录操作与结果。可快速固化的修复回本机提交；暂不值得自动化的写准确重做步骤。未做事项或真正故障不能写 PASS。

局部测试覆盖本次新增脚本/模板、缺必需参数/材料、初始化失败停止、重复Secret不重生以及实际启动。不要让 fake 扮演不真实协议。仅候选收敛后运行一次既有发布门禁；build内含gate就不再单独重复，纯文档不重编。SSH断开先看原进程、日志及退出码，不重发安装、不频繁全量抓取。

当前目标是已有集群应用部署并交付首装接入。**本轮默认不执行裸机重新安装。** 裸机步骤未跑记 not_run；需要另获干净目标授权再验证，不能拿现有集群补装当裸机一键成功，也不能为了这个待测项让本轮应用永远不交付。

本机提交/推送清楚列出的文件与本任务PR，不自动合并，不纳入并行代码。交付实际镜像映射、匹配包/脚本、部署与应用级重试命令、URL/管理员凭据取得方式、分项结果、人工事项与已知问题。阶段提交不是提前停止点；达到本轮目标后交审结束。

## 6. 最短处理规则

配置或 CA 错 → 只修本任务配置、复验真实进程；SQL错 → 只查相应文件/事务；缺料 → 一次列清并继续可做任务；共享资源冲突 → 只挂起冲突写入。不得将这些问题转换为重做 installer、换主CNI、恢复三台VM或重建全部应用镜像。

本包未读取用户新下载的镜像层，因此不声明实际镜像数量、版本或兼容性已经验证。接手时在 Fedora 从实际输入确定。
